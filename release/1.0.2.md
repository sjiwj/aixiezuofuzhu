开箱即用版。装好填个 key 就能写，不需要再自己搭网关。

## 这一版改了什么

### 新用户不再需要网关

上一版仓库里带的默认配置是 `gateway.enabled: true`，指向 `127.0.0.1:3000`。所有下载者继承这份默认——不自己跑一个网关，第一次点「写这一章」就报「目标计算机积极拒绝」。

现在出厂默认是**直连厂商**：

```
1. 打开软件 → 设置 → 模型
2. 填你自己的 key（不是占位符）
3. 点「测试连接」，看到成功就能写
```

不需要装任何额外服务。想统一管多个厂商、想在一个地方看账单，再自己去跑网关，设置里打开即可。

顺带修掉一个副作用：以前改设置会改到**仓库里**那份配置，`git status` 变脏、下次 pull 冲突。现在你的偏好写在数据目录（`%APPDATA%\novelapp-desktop\data\config\`），不碰代码库。

### 首次启动就把目录建好

来自真实反馈（issue #1）：全新装好后 `data_dir` 和 `projects` 都不存在，`/api/health` 报 `projects: false`，与 README 说的「首次会建数据目录」不符。

现在启动即创建 `data`、`data/projects`、`data/config`。

### 写之前先拦一道（省钱）

新加 `core/precheck_input.py`：在调模型**之前**检查输入。命中直接拒（`force=true` 可越过）：

- 章号不是 3 位数字
- 找不到本章大纲
- 输入里有占位残留：`{topic}` / `TODO` / `待补` / 空括号

只提示不拦（软缺）：大纲没有分场块、分场块缺「场次 / 必须做到 / 不许做」、覆盖已定稿章节。

一句话章纲会让模型自己铺 1200 字环境——这是真金白银的浪费，现在会先告诉你。

### 写盘红线

新加 `core/redline.py`：

```
隐藏路径（.stages.json / .layers/ / .trash/）       → 一律拒，无逃生口
已定稿章节被覆盖                                     → 需 force=true
已定稿章节被删除                                     → 需 force=true
```

修掉一个真实洞：之前能从 Web 写接口直接改 `.stages.json`，把定稿状态改回 draft，等于绕过整套阶段流转。

### 待办队列：下一个该写哪章

新加 `GET /api/queue` 与 `POST /api/queue/next`。

不新建数据源，只把已有的状态机、章节文件、大纲、错题本合起来排个序，每条都带理由：

```
+100  错题本有未处置条目（返工优先）
 +40  有本章章纲
 +20  有正文且状态是 draft/reviewing
 +10  有章纲但还没正文
 −50  已定稿
```

它只**建议**，不自动调模型——写不写仍由你决定。

### 发布前的自检工具

`scripts/_pre_publish_check.py`：一次查完密钥形态、本机用户目录、客户统计、具体书名、正文片段、凭据文件、`.gitignore` 覆盖。带 NFKC + URL 解码，全角写法和 `%2D%2Dbook` 也能识别。

`.githooks/pre-push`：往 github.com 推送前强制跑一遍，不过就阻断。安装一行：

```powershell
git config core.hooksPath .githooks
```
