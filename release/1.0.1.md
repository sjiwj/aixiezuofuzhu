# v1.0.1 —— 两个高危补丁 + 两处「看得见的别扭」

这是一个**只动入口与错误文案**的版本。写作逻辑、API 契约、界面操作流程都没变。

如果你在用 1.0.0：**升级**。1.0.0 有两个高危，见下。

---

## 安全修复（这两个是真的）

红队自测在 1.0.0 上复现了两条，都能在本机用 curl 打出来：

**N1 · Host 头伪造（DNS rebinding）**
`curl -H "Host: evil.example" http://127.0.0.1:8770/api/config` → 返回 200。
恶意域名只要解析到 127.0.0.1，就能同源读写你的接口。

现在：入口只认 `127.0.0.1` / `localhost` / `[::1]`，其余一律 403。局域网部署用环境变量 `NOVELAPP_ALLOW_HOSTS` 显式开白，默认不放。

**N2 · 跨站 Origin + 任意 Content-Type（CSRF 写文件）**
`curl -H "Origin: https://evil.example" -H "Content-Type: text/plain" -d '{"path":"projects/x.md","content":"y"}' /api/save` → 200，**文件真的被改写**。

现在：
- 写请求校验 `Origin`：必须同源；缺省放行（curl、CI、脚本照旧可用）；`Sec-Fetch-Site: cross-site` 直接 403；
- `Content-Type` 必须是 `application/json`；
- 跨站 + `text/plain` 的写文件路径已封死，文件不落地。

**N3 · `/api/chat` 无令牌**
现在没有 `X-Novelapp-Token` 一律 401。页面令牌由服务端注入（`window.__NVL_TOKEN__`），界面不用改、照常能写。

**N5 · `/api/tree?path=..`**
带 `path` 时走统一 `safe_rel` 校验，越界 400，不再静默归一化。

## 界面上的两处改进

**错误文案普通话化**
以前界面会直接吐 `KeyError: 'title'`、`JSONDecodeError: Expecting value`。现在是一句中文：

```
数据里缺字段「title」，可能是文件格式和当前版本对不上
返回内容不是合法 JSON（第 3 行第 7 列）
网络不通，检查模型网关是否在跑（默认 http://127.0.0.1:3000）
模型服务拒绝了这个 key（HTTP 401），去设置页换一个
```

英文原文与堆栈只写 `<data_dir>/logs/errors.log`，排障时去看那个文件。
覆盖 `server.py` 69 处 + `ai_detect` / `history` / `reviewers` / `planning` / `charge_guard` / `breakdown_ui` / `update_ledgers` 共 20 处。

**大纲 / 设定库有专用 API 了**
原来这两个入口靠 `/api/tree` + `/api/file` + `/api/save` 兜底，是 9 个入口里唯二标「待完善」的。

现在：

| 方法 | 路由 | 行为 |
|---|---|---|
| GET | `/api/outline?book=` | 列 `大纲/` 下的 md（标题 / 字数 / 改时间） |
| GET | `/api/outline?book=&name=` | 读单篇，附章纲校验结果 |
| POST | `/api/outline` | 写单篇；章纲不合格 400 且不动文件 |
| GET/POST | `/api/settings...` | 同上，作用于 `设定库/` |

**章纲在写盘前就按规范校验**（依据 `docs/架构-通用版/08-章纲分场规范.md`）：

- 场次表 4 列（场 / 地点·时辰 / 发生什么 / 约字数）
- ≥2 场
- 「必须做到的事」≥3 条
- 「不许做」≥1 条
- 文风锚点（只提醒，不挡）
- 「本章推进」若写了要有 `P-XXX` 编号（只提醒）

不合格不写盘，`force=true` 可以人工越过。`全书大纲.md` / `分卷大纲.md` 不校验。

9 个入口的 `missing` 从 2 降到 0。

## 顺手修的一个真问题

`/api/entries` 以前只报 `shipped_present: true`。但仓库里那个「发布包」是 11-05 的旧包（`server.py` 56KB vs 源码 262KB，只有 22%），**不含上面两个安全修复**。

现在会报：

```
shipped_stale: true
shipped_note: '发布包是旧版（56858 字节 vs 源码 262793 字节，仅 22%），含已知安全修复缺失，先重新构建再用'
```

## 已知限制（没修的，写在这）

- **`dist/` 与 `发布桌面版/` 还是旧包**。要用 exe 必须重新构建，别直接发仓库里那个。`/api/entries` 现在会告诉你它过期了。

- 真实上游失败路径（429 / 403 / 网关宕机）只做了单元级映射断言，没打真实故障。
